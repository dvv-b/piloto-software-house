- o_que_falhou: (1) saída com acento corrompida no Windows com pipe (cp1252), achada por teste manual; (2) editei arquivos com `python - <<EOF` e escapes (`\n`, `\xff`) foram interpretados e quebraram test_cli.py e o README duas vezes, derrubando a suíte e gerando um bloqueio falso do QA, que testava em paralelo
- causa: escapes em strings Python dentro de heredoc de shell; edições concorrentes enquanto agentes validavam
- licao: para texto com `\` e acentos, usar a ferramenta Edit (não script Python em heredoc); não editar arquivos enquanto qa/revisor os leem; em CLI que recebe dado pessoal, o argparse também ecoa a entrada (sobrescrever `error()`); CLIs Python no Windows precisam fixar UTF-8 nos fluxos
